# Security and authority
Training environment only unless officially authorised. Do not send actual government confidential records to external model providers. Real official PDFs may be public; internal training documents classified separately. Use fictional names, no real addresses/IDs/bank accounts or forged seals/signatures. Actual government deployment requires independent approval of hosting, model data handling, access, integrations and security.

Roles: leadership, supervisor, head_of_office, pension_assistant, grievance_officer, directorate_officer, audit_officer, system_admin. Default deny. Scope grants to workspace + office + case + classification + operation. System admin metadata/config only unless separate approved content grant. Grievance officer relevant restricted fields. Pension assistant assigned records and draft/propose only. Supervisor approval only within configured authority; no automatic authority based on designation. Audit officer authorised scope only. Separate approval from execution and verification. No model authority to approve, issue PPO, settle pension, dispose grievance or dispatch official correspondence unilaterally.

Check permissions before retrieval, snippet, preview, export, tool execution and every mutation. Private storage, short-lived signed URLs after access check or authenticated stream. Prevent IDOR and cross-workspace leaks. Use same-origin/CSRF protections, secure cookies, bounded session lifetime, server-side role validation, secrets only server-side. Sanitize rendered HTML, attachments MIME/size validation; do not run document instructions. Rate limit expensive requests. Never log passwords, session tokens, API keys or sensitive document text unnecessarily. Audit append-only: actor, action, resource/version, timestamp, outcome, policy, run/correlation ID. Keep denied events. Audit operations do not prove intent. Use idempotency and transactions; approved action payload immutable; any edit requires new approval. User may cancel unexecuted work; preserve historical decisions.

Approval states prepared → submitted → approved/returned/rejected → executed → verified. Record reason, reviewer, exact version, time, evidence; separate dispatcher and verifier if policy requires. Draft generation and authorised reads can be immediate. Official actions require actual authority and supported connector. Local workflow records must never imply government dispatch or external updates. No automatic knowledge publication on upload. Verify issuing authority, signature, effective date, rule conflict, scope before approval/publication. Preserve superseded rule and historical decisions.
