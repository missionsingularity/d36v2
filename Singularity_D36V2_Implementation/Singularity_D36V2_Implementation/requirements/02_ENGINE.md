Ontology links: pensioner HAS_PROPOSAL; proposal ASSIGNED_TO office/owner, HAS_OBJECTION, SUPPORTED_BY document, LINKED_TO grievance; officer REPORTS_TO officer, MEMBER_OF office, HAS_AUTHORITY scope; grievance REFERS_TO proposal; task RELATED_TO case and ASSIGNED_TO officer; approval REVIEWS exact document version or action payload; rule GOVERNS subject with applicability and effective date; knowledge change POTENTIALLY_AFFECTS case. Use relational queries, no separate graph DB required. Avoid invented edges. Distinguish internal reporting from coordination.

## Agent execution
1. Authenticated actor, scoped context and instruction.
2. Model returns typed plan from registered tools (schema validated, bounded tool calls/steps, no arbitrary SQL, source content is untrusted data not instructions).
3. Search retrieves allowed records and passages with full-text/semantic where available; exact IDs and metadata filters first. Return citations from retrieved source IDs, not model-generated identifiers.
4. Context uses deterministic functions for differences, counts, dates, entity resolution and relationships. Ambiguity or missing source prompts clarification; do not assert authority or legal conclusions without evidence.
5. Act validates all args, permission and approval requirements; transactionally save real records and append audit. Idempotency key per mutating step to avoid duplicate tasks on retry. External action only via approved connector with verified response. No arbitrary HTTP endpoints from user/model. Stream actual step statuses or poll run state. Bound timeouts, cancellation and recoverable errors. Persist run and result; never report complete while awaiting approval.

Tool contract examples: search_records(query,scope), get_case(id), get_source_passage(id,version,anchor), list_related(id), compare_service(proposal_id), calculate_backlog(filters), compare_grievance_outcome(id), query_audit(case_id,from), assess_policy_impact(doc_id), create_document(template,case_id,evidence_ids), revise_document(id,base_version,changes), export_document(id,version,format), create_task(case_id,assignee_id,description,due_date), submit_for_review(target_id,version,reviewer_id), record_decision(approval_id,decision,reason), propose_knowledge_change(source_id,scope), request_connection(app_id,purpose), get_connection_status(app_id), sync_authorised_records(app_id). Each returns structured success/error with persisted IDs, evidence and status; actor derived from session, never trusted input.

## Document pipeline
Import supplied Markdown source-records as immutable training originals (or render to PDF with actual pagination and record the mapping). For historical page 18 reference, preserve logical original page metadata; do not claim generated PDF physical page 18 unless actually created. Index section anchors and exact passages. Store content hash/version; citation viewer resolves correct source and anchor. Generate native DOCX/PDF/XLSX/PPTX on server with maintained libraries; export must open and contain supporting references. Protect downloads with server authorization. Generated drafts are versioned; every edit new version, approvals remain bound to prior version. For official reference PDFs fetch only official URLs from manifest, validate type, store source URL/hash/retrieval date, index actual pages, mark inaccessible as unavailable. No invented rule text.

## State and durability
Shared database for all UI and agent tools. Use existing auth or Supabase Auth, HttpOnly session cookies, stable shared layout. Verify identity once on initial load, revalidate as needed, authorize every server operation. Never cache identity across users. Distinguish signed-out vs unavailable. Keep persistent data across reload/deploy. No global in-memory fake DB in hosted mode. Use isolated training workspace and seed script; do not overwrite changed records on rerun. Scheduled work requires persistent job runner and actual deployment support; otherwise mark scheduling unavailable.
